# Git Workflow

- Terminology: the primary checkout is the canonical repository checkout for the task; an auxiliary worktree is an additional Agent Manager/task checkout. Both are Git worktrees, so do not use “worktree” alone to mean the auxiliary checkout.
- For a Kilo-managed worktree, the target branch is that worktree's recorded parent/base branch. Read it from the selected worktree's Agent Manager metadata (the worktree details expose its base branch; `.kilo/agent-manager.json` may be available as diagnostic state). Do not use the generated work branch, current branch, upstream, or an overrideable diff-comparison branch as a substitute. Git does not record which branch a worktree was created from, and the metadata file may not be present in every execution environment.
- If the recorded target branch or primary checkout cannot be identified from the task/Agent Manager context, ask the user before committing or pushing. Never guess `main`, the remote default branch, or a branch inferred from a merge base. If metadata is unavailable to the agent, state that limitation and ask for the target branch.
- Once the requested work and its required verification are complete, commit and push the intended changes to the recorded target branch by default without waiting for a separate request. Respect any explicit user instruction not to commit or push. If the target branch or primary checkout cannot be identified, or a safe transfer is unavailable, ask or report the blocker rather than guessing.
- Do not commit or push to a generated Kilo/task branch or auxiliary worktree unless the user explicitly asks for that branch. When the recorded target is known, use that branch, including `main`; do not ask again solely because the target is `main`.
- If work was done in an auxiliary worktree, transfer only the requested changes to the primary checkout on the recorded target branch, then commit/push there. Do not commit on the auxiliary task branch; if the primary checkout is unavailable or transfer cannot be done safely, stop and explain why.
- Before committing or pushing, verify the primary checkout path, recorded target branch, worktree list, working tree status, and upstream. Once the target is known, move the changes to that branch only if it is safe and does not discard unrelated work. Do not change branches or set an upstream to work around missing target-branch information. Exclude unrelated pre-existing changes.
- Do not remove a worktree unless explicitly requested and it is confirmed to be auxiliary; never remove the sole primary checkout.
